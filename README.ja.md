# Windows SMS Bridge · 短信桥

[English](README.md) | [简体中文](README.zh.md) | **日本語**

[android-agent-sms-bridge](https://github.com/tiny-andr/android-agent-sms-bridge) の Windows デスクトップクライアントです。端末にある SMS を、クラウドを経由せずに PC で閲覧・検索・自動同期できます。

```
┌────────────────┐   HTTPS + HMAC-SHA256   ┌──────────────────────┐
│  Android アプリ │ ◀─────────────────────▶ │  Windows SMS Bridge  │
│  SMS Bridge    │    同じ Wi-Fi / VPN     │  本アプリ             │
└────────────────┘                         └──────────────────────┘
```

## 端末のペアリング

1. 端末で **SMS Bridge** を開く → **サービスを有効化** → メイン画面のアドレスを控える（例: `https://192.168.1.100:8787`）
2. 端末の **ペアリング** 画面で 6 桁のコードを取得（**5 分間有効・1 回限り**）
3. PC で右上の **端末をペアリング** → アドレスとコードを入力 → **ペアリングして同期**
4. ダイアログに出る証明書フィンガープリントを、端末のペアリング画面の表示と照合する

初回接続時に端末の自己署名証明書を固定（TOFU）し、以降のリクエストはすべてその証明書で検証されるため、本文は常に暗号化されます。

端末は複数ペアリングできます。それぞれ独立した鍵を持ち、上部の端末バーにカードとして並びます。失効は端末側のペアリング一覧からいつでも可能です。

> Android アプリを更新すると証明書が変わり、古い鍵は使えなくなります。端末を右クリック → **再ペアリング（鍵・証明書の更新）** を選んでください。キャッシュ済みのメッセージは保持されます。

## 機能

| | |
|---|---|
| 複数端末 | 端末ごとに鍵・バッテリー・通信事業者・最終同期時刻を保持 |
| 手動同期 | 端末バーの **同期**（`Ctrl+R`）。選択中の端末、または全端末を同期 |
| 定期同期 | オフ / 1 / 5 / 15 / 30 / 60 分。バックグラウンドで静かに実行 |
| Windows 起動時に開始 | `Run` エントリを 1 つだけ登録。トレイで静かに起動することも可能 |
| トレイ常駐 | ウィンドウを閉じるとトレイへ。トレイメニューから同期・終了 |
| ビュー | すべて / 受信 / 送信済み / 未読。端末単位または全端末 |
| 会話ビュー | 番号ごとに集約、未読数、日付区切り、送受信の吹き出し |
| 検索 | 番号・本文のあいまい検索（`Ctrl+K`） |
| 書き出し | 会話単位または全件を CSV に（UTF-8 BOM、Excel でそのまま開ける） |
| テーマ | ダークガラス / ペーパー。タイトルバーから切り替え |
| 表示倍率 | 85 %–150 %。文字と余白をまとめて拡大縮小 |
| 言語 | English / 简体中文 / 日本語。既定はシステムに追従 |
| 読み取り専用 | 端末には一切書き込まない（送信も既読化もしない） |

## 同期の仕組み

- **初回同期**（ペアリング直後）: `GET /v1/sms?days=30&box=all&limit=200` で直近 30 日を offset でページング。
- **通常の同期**: `GET /v1/sms?since_id=<ローカル最大 id>&box=all` で新着のみ取得。
- 端末側の `_id` で重複を排除し、本文や既読状態が変わっていればローカル側を更新します。
- 端末ごとに同時 1 ジョブ。端末側の上限は毎分 60 リクエストで、通常の同期は 1 リクエストで完了します。

端末側は `days` を 30、`limit` を 200 に制限するため、それより古い履歴は端末側の上限を緩める必要があります。

## ソースからビルド

Node.js 18 以降が必要です。

```bash
npm install
npm start            # ソースから起動
npm run pack         # Windows 版を dist/ にパッケージ
npm run icons        # アイコンを再生成（Python + Pillow）
```

## データ

データはすべてこの PC の `%APPDATA%\Windows SMS Bridge\` に保存されます。

- `config.json` — ペアリング済み端末と設定。ペアリングトークンは Windows DPAPI で暗号化
- `messages.json` — ローカルのメッセージキャッシュ（平文 JSON。必要なら BitLocker で保護）

本アプリは読み取り専用です。端末への書き込み、SMS の送信、既読化は行いません。

## セキュリティモデル

- **通信は TLS。** 端末は自己署名証明書で HTTPS を提供し、初回ペアリング時にその証明書を固定（TOFU）、以降のリクエストは厳密に検証されます。同じ Wi-Fi での受動的な盗聴でも本文やトークンは読めません。
- **TLS に加えて署名。** 各リクエストは `X-Client-Id`、`X-Timestamp`、`X-Nonce` と、メソッド・パス・生のクエリ・タイムスタンプ・nonce に対する HMAC-SHA256 署名を伴います。改ざんとリプレイ（±5 分、nonce は 1 回限り）の両方に対応。
- **既知の限界。** 端末の秘密鍵は APK に含まれるため、この TLS は受動的な盗聴は防げても、APK から鍵を取り出せる相手には及びません。真正性の保証は最終的にトークンです（鍵がなければ署名できません）。
- **トークンの保存。** Windows DPAPI で暗号化し、この Windows アカウントだけが復号できます。
- **外部からのアクセス。** Tailscale / WireGuard を経由してください。8787 をインターネットへポート転送しないでください。

## トラブルシューティング

| 症状 | 原因 | 対処 |
|---|---|---|
| 接続が拒否される | 端末側のサービスが停止 | 端末アプリでサービスを有効化 |
| タイムアウト | 画面オフ後に ROM がアプリを凍結 | バックグラウンド許可・省電力オフにして再試行 |
| 「証明書が信頼されていない」 | 証明書が変わった（再インストール）／未ペアリング | 再ペアリング |
| 端末カードに「再ペアリングが必要」 | 端末側で鍵が失効した | 右クリック → **再ペアリング** |
| 受信トレイが空 | 直近 30 日にメッセージがない、または `READ_SMS` 未許可 | 権限と取得期間を確認 |
